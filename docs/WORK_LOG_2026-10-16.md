The Android debug build completed successfully. An installation failure was caused by an older installed application using the same Android package name but a different signing certificate:

```text
INSTALL_FAILED_UPDATE_INCOMPATIBLE
```

Removing the older package from the device allowed the current debug build to install. If `adb` is not available directly in PowerShell, the application can be removed from the phone's application settings or ADB can be run from the Android SDK `platform-tools` directory.

The environment file command must reference a real file without a trailing slash:

The real `supabase.env.json` should remain untracked if it contains environment-specific values. Commit only the sanitized example file.

## 6. Authentication and authorization expectations

- Public registration creates a customer/buyer account only.
- A customer must submit a seller application and complete the verification workflow before seller approval.
- Seller privileges must be activated only through a trusted backend or authorized approval process.
- Changing a client-visible role field must never grant seller or administrator access.
- Administrator accounts must be provisioned through a trusted process, not public registration.
- Supabase Row Level Security and server-side checks remain the source of truth for permissions.
