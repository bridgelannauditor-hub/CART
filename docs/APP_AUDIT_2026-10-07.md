# C+ART application audit — 2026-10-07

## Verification performed

- Reviewed all 120 Dart files plus Android, iOS, Firebase, and dependency configuration.
- Ran Flutter analysis by module. It found no compile errors or warnings and 73 info-level findings, mostly deprecated Flutter APIs and style findings.
- Built the Android debug APK successfully.
- The voucher, credential-free user mapping, and route-guard suites pass all 12 tests.
- The full Flutter test command passes; the obsolete empty `widget_test.dart` file was removed.
- Dependency audit found 14 direct/transitive constraints behind resolvable versions and a discontinued transitive `js` package.

## P0 — release blockers

1. **Fixed locally: Firestore authorization and trusted commerce, review, profile, and product creation functions are implemented.**
   `firestore.rules`, `firestore.indexes.json`, callable Cloud Functions, emulator configuration, and automated rule/integration suites now live in the repository. The rules bind access to `request.auth.uid`, deny direct profile/product/counter/order/follower/voucher/review mutations, protect rating aggregates, and deny unknown collections by default. Numeric user and product IDs are allocated in transactions that reconcile the counter with existing records. The remaining release step is a controlled staging deployment with functions deployed before rules. See `docs/FIRESTORE_SECURITY.md`.

2. **Fixed locally: checkout is now a trusted atomic transaction.**
   The `placeOrder` callable derives customer identity from Firebase Auth, validates the delivery address and payment method, reloads authoritative prices/options/stock, calculates each seller subtotal and voucher discount, decrements inventory, creates the order, redeems vouchers, and creates seller notifications in one transaction. Direct client order writes are denied.

3. **Fixed locally: fulfillment is isolated per seller.**
   Each order now contains server-owned `sellerFulfillment` records. The seller callable derives the seller from Firebase Auth, updates only that seller's line items and tracking, enforces forward status transitions, and derives the aggregate customer-facing status.

4. **Fixed locally: plaintext password storage has been removed.**
   Database version 17 rebuilds the local users table without the password column, permanently discarding values retained by existing installations. New databases omit the column, `UserModel` contains no credential field, and the obsolete SQL login/password-update methods and credential debug logging are removed. Firebase Auth is the only credential store.

5. **Fixed locally: order reads are scoped to the signed-in party.**
   Customer reads now query `customerId`; seller reads query `sellerIds` with `arrayContains`. Server data is preferred with a cache fallback, and the required composite indexes are declared in `firestore.indexes.json`.

## P1 — correctness and account failures

6. **Fixed locally: order refresh now prefers server data.**
   Scoped order queries request the server first with an eight-second timeout and use the Firestore cache only as an offline fallback.

7. **Fixed locally: email and social login rebuild the compatibility profile.**
   Both login paths now recreate the local sqflite profile mirror when it is absent, using the server-owned numeric user ID and no local credential field.

8. **Fixed locally: profile email changes now follow Firebase's verified-email flow.**
   A requested email change calls `verifyBeforeUpdateEmail` and keeps the current verified address in Firestore and sqflite until Firebase confirms the change. Session restoration refreshes the ID token and synchronizes a newly verified Firebase address into both profile stores. Firestore rules also require the profile email to match the authenticated token email.

9. **Fixed locally: registration reconciles ambiguous callable results.**
   If profile creation reports an error after the server transaction may have committed, registration checks Firestore first. It keeps a completed account and rebuilds the local mirror, or removes the new Firebase Auth account when no profile exists.

10. **Partially fixed: Google sign-in is provisioned for Android debug builds.**
    The Firebase Google provider is enabled, its public-facing project name is `C+ART`, the Android debug SHA-1 and SHA-256 fingerprints are registered, and `google-services.json` now contains Android and web OAuth clients. A real release signing key and its fingerprints are still required before release. Facebook resources still contain placeholder values even though the Firebase provider is enabled, and the iOS Firebase plist/provider URL schemes remain absent.

11. **Fixed locally: Firebase sessions are restored and named routes enforce account roles.**
    The splash screen reloads the current Firebase user, refreshes the token, rebuilds the local profile mirror, and routes customers and sellers to their respective home screens. Named routes redirect anonymous users to login and prevent customer/seller cross-role navigation; five route-guard tests cover these cases.

## P1 — checkout, payments, and commerce gaps

12. **GCash, Maya, and bank transfer are labels only.**
    Selecting a non-COD method still places the order immediately with `Awaiting payment confirmation`; there is no payment provider, account destination, proof upload, webhook, reference number, timeout, or reconciliation flow.

13. **Cart, favorites, delivery addresses, and settings are device-local.**
    These disappear after reinstall/reset and do not follow the account to another device. Delivery addresses also cannot be recovered on a fresh device even though checkout requires one.

14. **Fixed locally: order IDs are allocated inside the server transaction.**
    The checkout function advances the `counters/orders` document atomically and uses the server clock only to initialize a missing counter.

15. **Fixed locally: reviews and rating aggregates use a trusted transaction.**
    `submitReview` derives the customer from Firebase Auth, requires a delivered line item for that product, validates the rating and comment, enforces one deterministic review document per customer/product pair, and updates `ratingTotal`, `rating`, and `reviewCount` atomically. Direct review writes and seller changes to aggregate fields are denied.

## P1 — LIVE feature gaps

16. **All sellers share one Agora channel and one Firestore LIVE document.**
    `test-room` allows only one platform-wide session. A second seller overwrites the first session. Use a per-broadcast document and channel generated from a server-issued broadcast ID.

17. **The Agora token is hardcoded and temporary.**
    It will expire and is bundled in the APK. Production requires a token service that authenticates the user, checks seller permission, and issues short-lived per-channel tokens.

18. **Blocked viewers persist across unrelated broadcasts.**
    `blockedUsers` is stored under the shared `test-room` session and is never cleared or scoped by broadcast/seller.

19. **LIVE scope is incomplete.**
    Product display, pinning, comments, hearts, in-app follower records, and basic moderation exist. Co-hosts/guests, replay/recording, scalable viewer presence, and real device push notifications are absent.

## P2 — reliability, performance, and UX

20. **Partially fixed locally: high-volume customer lists are paginated.**
    Customer and seller order screens, the customer home product feed, filtered category grids, notification inbox, conversations, followed-shop row, customer voucher history, review repository, seller dashboard products, and customer shop product grids now query 20 documents at a time and continue with stable Firestore cursors. Checkout queries only currently usable vouchers, while profile voucher and followed-shop totals use aggregate counts. Seller and storefront product totals, units sold, review totals, weighted ratings, low-stock totals, and best-seller selection now use bounded aggregate or limited queries. The storefront separately loads at most ten flash-sale and ten top-selling products instead of scanning the catalog. Seller dashboard revenue reads only the current and previous months; detailed analytics reads the selected year plus the preceding December instead of all order history. The newest conversation page remains live while older conversations load on demand, and the navigation badge uses a Firestore sum aggregation instead of downloading every conversation. Follower-campaign analytics use Firestore count and sum aggregations for new followers, redemptions, and revenue while reading the trusted claimed counter from the campaign. A seller with unusually high order volume within one analytics year can still create a large date-scoped read.

21. **Fixed locally: bulk read-state updates stay below Firestore batch limits.**
    `markAllRead` and `markConversationRead` now query and commit unread documents in chunks of 450. Conversation unread counters are cleared only after all message chunks succeed, so accounts with long histories no longer create oversized write batches.

22. **Many failures are silently swallowed.**
    Inventory updates, product loading, cart cleanup, notifications, live cleanup, and other paths contain empty `catch` blocks. Add structured logging, retry/reconciliation jobs, and clear user-facing recovery states.

23. **Fixed locally: registration social buttons now authenticate.**
    Google and Facebook controls invoke their providers, show per-provider loading state, require acceptance of the terms, preserve the selected customer/seller role for a newly created profile, require a shop name for social seller registration, initialize the session, and route to the correct dashboard.

24. **Fixed locally: Settings displays the correct account type.**
    The account row now uses the normalized session role helper, so sellers are no longer shown as customers because of a case mismatch.

25. **Fixed locally: media selection checks widget lifetime.**
    Photo and video selection now verify that the originating context remains mounted after the native picker returns before showing messages or notifying the parent.

26. **Fixed locally: noninteractive revenue bars no longer expose empty actions.**
    Daily revenue bars omit the tap callback and accessibility button role, while monthly bars retain their working month-selection action.

27. **Partially fixed locally: in-app notification preferences now work across devices.**
    The in-app, order-update, and promotion switches sync to the authenticated Firestore profile while retaining a local offline mirror. Trusted checkout/cancellation/fulfillment operations and seller LIVE announcements consult the recipient's preferences before creating an inbox notification. Email delivery is labeled “Coming soon”; Firebase Cloud Messaging and real email delivery are still absent.

28. **Release/platform configuration is unfinished.**
    Android release builds use the debug signing key. iOS lacks `Podfile` and `GoogleService-Info.plist`, plus Google/Facebook URL schemes. Linux Firebase is explicitly unsupported.

29. **Cloudinary unsigned upload needs production controls.**
    Partially fixed locally: all upload paths now validate supported image/video extensions and reject empty or oversized files (10 MB images, 100 MB videos), use a 90-second timeout, and avoid exposing raw provider errors. The public unsigned preset is expected in a client, but the Cloudinary account must still enforce matching file-type and size limits, transformations, rate/usage monitoring, and abuse controls.

30. **Maintenance and test coverage remains incomplete.**
    Voucher, credential-free user mapping, route guards, and media validation have 16 unit/widget tests, Firestore authorization has 14 emulator tests, and trusted operations have 16 integration tests covering checkout, notification preferences, stock, seller isolation, cancellation, follower vouchers, reviews, rating aggregation, concurrent numeric allocation, idempotent profiles, and server-owned product creation. Authentication provider UI, chat, and LIVE flows still lack automated coverage. The project README now documents setup and deployment, the stray `.dar.dart` file was removed, and `flutter analyze` reports no issues after the deprecated UI APIs and style findings were migrated.
